# 노트/리스트 창 UI 6차 개편 (리스트 압정, 아이콘 정리, 기본 글꼴)

## 배경

실제 패키징해서 써본 뒤 나온 개선 요청들이다. 리스트 창에 노트 창처럼 "항상 위에 고정" 기능이 없다는 점, 타이틀바 첫 줄의 여백, 검색창/태그 필터 글자 크기가 리스트 글씨 크기 설정에 같이 딸려 바뀌는 점, 톱니바퀴 아이콘이 비대칭으로 찌그러져 보이는 점(실제 캡처로 확인됨), 노트 창 색상 스와치의 선택 테두리, 기본 글꼴을 명시적으로 "돋움"으로 지정하는 것, 그리고 아이콘 중 ×만 유독 얇아 보이는 것을 다듬는다.

아이콘 크기는 실제로 두 가지 크기(28px, 22px)를 렌더링해서 비교한 뒤 현재 크기(28px)를 유지하기로 확정했다 — 대신 ×가 SVG가 아니라 텍스트 글자라서 ⚙(SVG)보다 가늘어 보이던 문제를 SVG 아이콘으로 교체해 해결한다.

## 요구사항

### 1. 데이터 모델

- `AppSettings`에 `listAlwaysOnTop: boolean`을 추가한다(기본값 `false`). `listFontSize`와 같은 방식으로 `updateSettings`를 통해 갱신되고 저장된다.
- main 프로세스: 리스트 창을 생성할 때 저장된 `listAlwaysOnTop` 값을 `BrowserWindow`의 `alwaysOnTop` 옵션으로 넘긴다. `listAlwaysOnTop`이 바뀌면 이미 떠 있는 리스트 창에도 `setAlwaysOnTop()`으로 즉시 반영한다(노트 창의 `setNoteAlwaysOnTop` 패턴과 동일).

### 2. 리스트 창

- 타이틀바 맨 왼쪽(드래그 영역보다 앞)에 압정 아이콘을 추가한다. 모양은 노트 창의 압정 아이콘과 동일한 SVG를 재사용한다. 클릭하면 `listAlwaysOnTop`을 토글하고, 활성 상태 스타일(진한 색)도 노트 창 압정과 동일하게 맞춘다. 기본은 꺼진 상태.
- 타이틀바 아이콘들(압정·⚙·×)의 버튼 크기는 지금과 동일하게 28px을 유지한다. **× 아이콘을 지금의 텍스트 글자(`×`)에서 ⚙과 동일한 크기(18px)의 SVG X 아이콘으로 바꾼다** — 지금은 텍스트 글자라서 ⚙(SVG)보다 가늘고 작아 보이는데, 이를 SVG 두 줄 교차 아이콘으로 바꿔 시각적 굵기/크기를 ⚙과 맞춘다.
- 타이틀바의 세로 패딩을 지금(`8px`)보다 살짝 줄여(예: `6px`) 첫 줄이 휑해 보이지 않게 한다. 압정 아이콘이 추가되면서 빈 드래그 영역도 자연히 줄어든다.
- 검색창 placeholder를 `"검색 (텍스트 또는 #태그)"`에서 `"검색"`으로 단순화한다.
- 검색창 글자 크기를 18px로 고정한다 — 지금처럼 `--list-font-size` 변수를 쓰지 않고 하드코딩해서, ⚙(글씨 크기 설정)를 바꿔도 검색창 글자 크기는 변하지 않는다.
- 검색창 아래 태그 필터(전체/#태그 버튼)의 글자 크기를 15px로 고정한다(검색창보다 살짝 작게). 이것도 ⚙ 설정과 무관하게 항상 15px이다.
- ⚙(글씨 크기 설정)의 영향 범위는 리스트 카드 본문(`.list-app__note-content`)에만 한정된다 — 검색창과 태그 필터는 제외.
- 헤더의 "+"(새 메모) 버튼이 창을 좁게 줄여도 잘리거나 사라지지 않도록 `flex-shrink: 0`을 지정한다.

### 3. 노트 창

- 색상 스와치의 "선택됨" 표시(회색 outline)를 제거한다 — 스와치는 선택 여부와 무관하게 항상 같은 모양으로 보인다(노트 배경색 자체가 이미 선택된 색을 보여주므로).
- 우측 아이콘(☰·⚙·×)의 버튼 크기는 지금과 동일하게 28px, 아이콘 크기 20px을 유지한다. **× 아이콘을 텍스트 글자에서 ⚙/☰과 동일한 크기(20px)의 SVG X 아이콘으로 바꾼다.**

### 4. 공통

- 톱니바퀴(⚙) 아이콘을 완전히 대칭인 모양으로 새로 그린다. 지금 쓰는 손으로 그린 path는 톱니 간격이 고르지 않아 찌그러져 보인다(실제 캡처로 확인). 원(하나 또는 두 개의 동심원으로 가운데 구멍 표현) + 일정한 각도로 균등 배치한 사각형 톱니 8개로 구성해, 코드 상에서 대칭이 기하학적으로 보장되도록 만든다. 노트 창·리스트 창 두 군데 모두 이 새 아이콘으로 교체한다.
- × 아이콘도 두 창 모두 SVG(두 줄이 X자로 교차하는 형태, `stroke-linecap="round"`)로 통일한다.
- 기본 글꼴을 `'Dotum', '돋움', sans-serif`로 지정한다(`.note-app`, `.list-app`의 `font-family`). 노트 본문(`.note-app__content`)은 지금처럼 `font-family: inherit`이므로 자동으로 이 글꼴을 따라간다.

### 5. 변경하지 않는 것

- 노트별 `fontSize`(작게/중간/크게 팝오버)와 리스트의 `listFontSize` 분리 구조는 그대로 둔다 — 이번 라운드는 검색창/태그 필터를 그 분리 범위에서 완전히 빼는 것뿐이다.
- 압정(노트 창)·색상 선택·태그 추가/삭제·검색/필터 로직·리사이즈/드래그는 그대로 둔다.
- 아이콘 버튼 크기(28px)는 이번에 다시 줄이지 않는다 — 지난 라운드에서 이미 결정한 크기를 유지한다.

## 구현 메모

- `createListWindow`는 현재 인자를 받지 않는데, `listAlwaysOnTop` 초기값을 읽으려면 `store`(또는 최소한 `AppSettings`)를 인자로 받도록 시그니처를 바꿔야 한다. `main/index.ts`의 세 호출 지점(`createTray(() => createListWindow(store))`, 최초 `createListWindow(store)` 호출, `app.on('activate', ...)`)을 모두 함께 고친다.
- `updateSettings`의 검증 로직에 `listAlwaysOnTop`(boolean 여부 확인) 분기를 추가한다. 값이 바뀌면 main 쪽에서 실제 리스트 창에 `setAlwaysOnTop()`을 호출해야 하므로, `UPDATE_SETTINGS` IPC 핸들러가 `changes.listAlwaysOnTop !== undefined`일 때 새 콜백(예: `setListAlwaysOnTop`, 노트 창의 `setNoteAlwaysOnTop`과 같은 패턴)을 호출하도록 `WindowCallbacks`를 확장한다.
- 톱니바퀴/×의 새 SVG는 노트 창과 리스트 창에서 각각 그 창의 기존 아이콘 크기에 맞춰 렌더링하되(20px vs 18px), 두 파일에 동일한 path 구조를 복사해서 쓴다(기존에도 두 창의 아이콘 CSS/마크업은 창마다 따로 두는 방식을 써 왔다).

## 테스트

- `npm run typecheck`, `npm test`, `npm run build`로 회귀를 확인한다. `listAlwaysOnTop`이 `AppSettings`에 추가되므로 `tests/store.test.ts`의 설정 관련 테스트(기본값, 업데이트, 유효성 검증)에 케이스를 추가한다.
- Xvfb + CDP로 두 창을 띄워: 리스트 창 압정 클릭 시 실제로 항상 위 고정이 되는지(다른 창 뒤로 안 숨겨지는지), 앱 재시작 후에도 압정 상태가 유지되는지, 타이틀바 첫 줄이 좁아졌는지, 검색창/태그 필터 글자 크기가 ⚙를 바꿔도 그대로인지(카드 본문만 바뀌는지), "+"버튼이 창을 좁혀도 안 사라지는지, 노트 창 스와치에 테두리가 안 보이는지, 톱니바퀴와 × 아이콘이 대칭이고 서로 크기가 비슷해 보이는지, 기본 글꼴이 돋움으로 렌더링되는지 확인한다.
