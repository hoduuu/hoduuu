# 스티커 메모 앱 설계

## 개요

데스크톱용 스티커 메모 프로그램. 화면에 자유롭게 띄워두는 개별 메모 창과, 태그 기반으로
전체 메모를 검색/분류할 수 있는 리스트 창으로 구성된다. macOS/Windows/Linux에서 동작하는
크로스플랫폼 앱이며, 모든 데이터는 로컬에만 저장된다.

## 목표 / 범위

- 실제 스티커 메모처럼 화면 위에 자유롭게 배치하는 개별 메모 창
- 메모마다 `#키워드` 형태의 태그를 붙이고, 태그/본문 텍스트로 검색·분류
- 로컬 전용 저장 (계정, 서버, 클라우드 동기화 없음)

## 목표가 아닌 것 (Out of scope)

- 글씨체/글자 크기 등 텍스트 스타일 커스터마이징 (추후 별도 스펙으로 추가 가능)
- 클라우드 동기화, 다중 기기 간 공유
- E2E 자동화 테스트 (규모상 과함, 필요 시 추후 추가)

## 1. 아키텍처

```
┌─────────────────────────────────────────┐
│           Electron Main 프로세스           │
│  - 메모 데이터 CRUD (electron-store)       │
│  - 윈도우 생성/관리 (리스트창 1개 + 노트창 N개) │
│  - IPC 허브 (창 간 데이터 동기화 브로드캐스트)  │
│  - 시스템 트레이 아이콘 (앱 상주)            │
└─────────────────────────────────────────┘
        │                    │
        ▼                    ▼
┌───────────────┐   ┌──────────────────┐
│  리스트 창 (React) │   │  노트 창 × N (React) │
│  - 전체 메모 목록   │   │  - 텍스트 편집       │
│  - 태그 필터/검색   │   │  - 색상 변경        │
│  - 항목 클릭 시     │   │  - 항상 위 토글      │
│    해당 노트창 열기  │   │  - 자유 이동/크기조절  │
└───────────────┘   └──────────────────┘
```

핵심 원칙:

- **단일 진실 공급원**: 메모 데이터는 Main 프로세스가 소유하고 로컬 파일에 저장한다.
  각 창(Renderer)은 IPC를 통해서만 데이터를 읽고 쓴다.
- **앱 상주**: 노트 창이나 리스트 창을 닫아도 앱은 종료되지 않고 트레이 아이콘으로 남는다.
- **실시간 동기화**: 한 창에서 데이터를 바꾸면 열려 있는 다른 모든 창에 즉시 반영된다.

## 2. 기술 스택

- **런타임**: Electron (macOS/Windows/Linux 크로스플랫폼)
- **UI**: React + TypeScript
- **저장소**: `electron-store` (JSON 파일 기반 로컬 저장)

SQLite 등 네이티브 DB 모듈은 채택하지 않는다. 이 앱 규모(개인용, 수백 개 메모 수준)에서는
과한 선택이며, 네이티브 모듈은 OS/아키텍처별로 별도 빌드가 필요해 크로스플랫폼 빌드를
복잡하게 만든다.

## 3. 데이터 모델

```typescript
interface StickyNote {
  id: string;              // UUID
  content: string;         // 메모 텍스트
  color: string;           // 배경색 (hex, 예: "#FFF59D")
  tags: string[];          // 키워드 태그, 예: ["API키", "깃허브"]
  position: { x: number; y: number };
  size: { width: number; height: number };
  alwaysOnTop: boolean;    // 항상 최상위 여부 (노트별 토글, 기본값 true)
  isOpen: boolean;         // 현재 화면에 떠 있는지 (닫아도 데이터는 유지, 삭제 아님)
  createdAt: number;       // epoch ms
  updatedAt: number;
}
```

저장 파일 구조: `{ notes: StickyNote[] }` 단일 배열. 이 규모에서는 별도 인덱스 없이
메모리에 올려 필터링해도 충분히 빠르다.

**태그/검색:**

- 태그는 자유 텍스트 배열이며 미리 정의된 목록이 없다. `#API키`처럼 입력하면 자동 등록된다.
- 검색은 (1) 태그 완전/부분 일치, (2) 본문 텍스트 부분 일치를 함께 지원한다.
- 태그 필터 사이드바에는 모든 노트의 `tags`를 모아 중복 제거한 목록을 표시한다.

**재시작 동작:** 앱을 재시작하면, 종료 시점에 `isOpen: true`였던 모든 노트 창을
자동으로 다시 띄운다.

## 4. 컴포넌트 & IPC 흐름

| 컴포넌트 | 역할 |
|---|---|
| Main 프로세스 | 데이터 저장/조회 전담, 창 생성·추적, 트레이 아이콘, 앱 시작 시 `isOpen=true`인 노트 자동 복원 |
| List 창 (React, 1개) | 전체 메모 목록, 태그 필터, 검색창, "새 메모" 버튼 |
| Note 창 (React, N개) | 텍스트 편집(디바운스 자동저장), 색상 피커, always-on-top 토글. 드래그/리사이즈는 OS 네이티브 창 기능 사용 |

**IPC 채널** (Main ↔ Renderer, `contextBridge`로 노출):

```
renderer → main:  notes:create, notes:update, notes:delete, notes:getAll
main → renderer:  notes:changed  (데이터가 바뀔 때마다 열려 있는 모든 창에 브로드캐스트)
```

흐름 예: 리스트 창에서 태그 수정 → `notes:update` 전송 → Main이 저장소 갱신 →
저장 성공 시 열려 있는 모든 창(리스트 + 해당 노트 창 포함)에 `notes:changed` 브로드캐스트 →
각 창이 자신의 state를 갱신한다.

**창 열기/닫기:**

- 리스트에서 노트 클릭 → 이미 열려 있으면 포커스만, 없으면 `BrowserWindow`를 새로 만들고
  `isOpen: true`를 저장한다.
- 노트 창 X 버튼 → `close` 이벤트를 가로채(`preventDefault`) 창을 숨기고(`hide()`)
  `isOpen: false`만 저장한다 (데이터는 삭제되지 않는다).
- 리스트에서 "삭제" → 확인 다이얼로그("정말 삭제하시겠습니까?")를 띄우고, 확인 시에만
  데이터를 삭제하고 열려 있던 노트 창도 닫는다.

## 5. 에러 처리

- **저장 실패**: `electron-store` 쓰기 실패(디스크 꽉 참 등) 시 렌더러에 에러 이벤트를
  전달하고, 노트 창 상단에 짧은 경고 배너("저장 실패, 다시 시도하세요")를 표시한다.
  실패한 변경사항은 재시도할 수 있도록 렌더러 로컬 state에 유지한다.
- **손상된 데이터 파일**: 시작 시 JSON 파싱에 실패하면 앱을 종료하지 않고 빈 목록으로
  시작하며, 기존 손상 파일은 `.bak`으로 백업해 사용자가 복구를 시도할 수 있게 한다.
- **중복 창 생성 방지**: 같은 노트 ID로 이미 창이 열려 있으면 새로 만들지 않고 기존
  창에 포커스를 준다.

## 6. 테스트 방식

- **단위 테스트**: 데이터 CRUD 로직, 태그 파싱/검색 필터링 함수 (Vitest). Electron
  없이 순수 로직만 분리해 테스트한다.
- **수동 검증**: 창 생성/드래그/리사이즈/트레이처럼 OS 레벨 동작은 자동화보다 실제
  실행으로 확인한다 (macOS/Windows 각 최소 1회).
- E2E(Playwright 등)는 이 규모의 개인 프로젝트엔 과하다고 판단해 제외한다. 필요해지면
  추후 추가한다.
